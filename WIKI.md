## Introduction

**Dozzle Agent** is a backend service add-on for Home Assistant that allows you to monitor Docker containers remotely from a main Dozzle instance. This add-on runs **only** the Dozzle agent (backend, no UI) on port 7007.

### Key Features

- ✅ Backend agent for Dozzle
- ✅ Remote Docker container monitoring
- ✅ Lightweight and efficient
- ✅ No web interface (backend only)
- ✅ Multiple agents support
- ✅ Full Docker socket access

> ⚠️ **Important Notes:**
> - This is **not** an official add-on from Dozzle
> - This add-on has **NO web interface** - it's a backend agent only
> - You need a main Dozzle instance to connect to this agent

## Prerequisites

Before installing the Dozzle Agent add-on, ensure you have:

1. **Home Assistant** installed and running (Supervisor mode)
2. **Docker** access enabled on your Home Assistant instance
3. **Network connectivity** between your Home Assistant instance and your main Dozzle instance
4. A **main Dozzle instance** running (can be on the same or different machine)

### Supported Architectures

The add-on supports the following architectures:
- `aarch64` (ARM 64-bit)
- `amd64` (x86_64)
- `armhf` (ARM 32-bit hard float)
- `armv7` (ARMv7)
- `i386` (x86 32-bit)

## Installation

### Step 1: Add the Repository

1. Open **Home Assistant**
2. Navigate to **Supervisor** → **Add-on Store**
3. Click on the **three dots menu** (⋮) in the top right corner
4. Select **Repositories**
5. Click **Add** and paste the following URL:
   ```
   https://github.com/Erreur32/homeassistant-dozzle-agent
   ```
6. Click **Add** to confirm

### Step 2: Install the Add-on

1. In the **Add-on Store**, search for **"Dozzle Agent"**
2. Click on **Dozzle Agent** to open its page
3. Click **Install** and wait for the installation to complete
4. The installation process will download the Docker image and set up the add-on

### Step 3: Configure the Add-on

1. Before starting, go to the **Configuration** tab
2. Configure the basic options (see [Configuration](#configuration) section below)
3. Click **Save** to apply the configuration

### Step 4: Start the Add-on

1. Go to the **Info** tab
2. Click **Start** to launch the Dozzle Agent
3. The agent will start listening on port **7007**
4. Check the **Log** tab to verify the agent is running correctly

## Configuration

The Dozzle Agent add-on has a simple configuration with two main options:

### Basic Configuration Options

```yaml
# Log level: Controls the verbosity of logs
# Options: debug, info, error
# Default: info
log_level: info

# Hostname: Optional hostname that appears in the Dozzle UI
# Leave empty to use the default hostname
# Default: ""
hostname: ""
```

### Configuration Explanation

#### `log_level`

Controls the verbosity of the logs generated by the agent:

- **`debug`**: Most verbose, shows detailed debugging information
- **`info`**: Standard logging level, shows general information (recommended)
- **`error`**: Only shows error messages

**Example:**
```yaml
log_level: debug
```

#### `hostname`

An optional hostname that will be displayed in your main Dozzle instance's UI. This helps identify different agents when you have multiple agents connected.

**Example:**
```yaml
hostname: "Home Assistant Server"
```

**Empty value:**
```yaml
hostname: ""
```

### Complete Configuration Example

```yaml
log_level: info
hostname: "My Home Assistant"
```

## Usage

### Understanding the Architecture

The Dozzle Agent works as follows:

1. **Dozzle Agent** (this add-on) runs on your Home Assistant instance
2. It listens on port **7007** for connections
3. Your **main Dozzle instance** connects to this agent
4. The main Dozzle instance displays logs from containers accessible to the agent

### Connecting from Main Dozzle Instance

#### Step 1: Find Your Home Assistant IP Address

1. In Home Assistant, go to **Settings** → **System** → **Network**
2. Note your Home Assistant IP address (e.g., `192.168.1.200`)
3. Alternatively, use your Home Assistant hostname if configured

#### Step 2: Configure Your Main Dozzle Instance

You need to configure your main Dozzle instance to connect to the agent. The connection details are:

- **Host**: Your Home Assistant IP address or hostname
- **Port**: `7007`

### Docker Compose Configuration

If you're running Dozzle using Docker Compose, add the following environment variable:

```yaml
services:
  dozzle:
    image: amir20/dozzle:latest
    container_name: dozzle
    environment:
      # Connect to the Dozzle Agent on Home Assistant
      - DOZZLE_REMOTE_AGENT=192.168.1.200:7007
    ports:
      - 8080:8080
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
    restart: unless-stopped
```

**Important:** Replace `192.168.1.200` with your actual Home Assistant IP address.

### Docker Run Command

If you're running Dozzle using `docker run`:

```bash
docker run -d \
  --name dozzle \
  -p 8080:8080 \
  -v /var/run/docker.sock:/var/run/docker.sock:ro \
  -e DOZZLE_REMOTE_AGENT=192.168.1.200:7007 \
  amir20/dozzle:latest
```

### Multiple Agents Configuration

You can connect to multiple Dozzle Agents from a single Dozzle instance. Simply separate the agent addresses with commas:

**Docker Compose Example:**
```yaml
services:
  dozzle:
    image: amir20/dozzle:latest
    environment:
      - DOZZLE_REMOTE_AGENT=192.168.1.200:7007,192.168.1.201:7007,192.168.1.202:7007
    ports:
      - 8080:8080
```

**Docker Run Example:**
```bash
docker run -d \
  --name dozzle \
  -p 8080:8080 \
  -e DOZZLE_REMOTE_AGENT=192.168.1.200:7007,192.168.1.201:7007,192.168.1.202:7007 \
  amir20/dozzle:latest
```

### Verifying the Connection

1. Start your main Dozzle instance
2. Open Dozzle in your browser (typically `http://localhost:8080`)
3. You should see containers from your Home Assistant instance listed
4. If you configured a `hostname`, it will appear in the Dozzle UI

## Troubleshooting

### Build Error: DNS Resolution Failure

**Problem:** Installation/build fails with DNS timeout error:

```text
ERROR: failed to build: failed to solve: failed to fetch anonymous token: 
Get "https://auth.docker.io/token?scope=repository%3Aamir20%2Fdozzle%3Apull&service=registry.docker.io": 
dial tcp: lookup auth.docker.io on 127.0.0.11:53: read udp 127.0.0.1:38495->127.0.0.11:53: i/o timeout
```

This error occurs when Home Assistant OS cannot resolve DNS to reach Docker Hub during the add-on build process.

**Solutions:**

1. **Check DNS Configuration in Home Assistant:**
   - Go to **Settings** → **System** → **Network**
   - Verify DNS servers are configured correctly
   - Try adding public DNS servers like `8.8.8.8` (Google) or `1.1.1.1` (Cloudflare)
   - Click **Save** and restart Home Assistant

2. **Verify Network Connectivity:**
   - Ensure your Home Assistant VM/host has internet connectivity
   - Test DNS resolution from Home Assistant:
     - Go to **Developer Tools** → **YAML**
     - Or use SSH add-on to test: `nslookup auth.docker.io`
   - Verify you can reach Docker Hub: `ping registry-1.docker.io`

3. **Check VM Network Settings:**
   - If running in a VM, verify the network adapter is properly configured
   - Ensure the VM has access to the host network or internet
   - Check if any firewall or network restrictions are blocking Docker Hub access

4. **Restart Home Assistant Supervisor:**
   - Go to **Settings** → **Add-ons** → **Dozzle Agent**
   - Click **Stop** (if running)
   - Go to **Supervisor** → **System** → Click **Restart** on Supervisor
   - Wait for restart, then try installing again

5. **Check Home Assistant System Logs:**
   - Go to **Settings** → **System** → **Logs**
   - Look for DNS or network-related errors
   - Check Supervisor logs for build errors

6. **Alternative: Pre-download Docker Image (Advanced):**
   - If DNS issues persist, you may need to configure Docker to use a different DNS server
   - This requires SSH access and Docker daemon configuration
   - Contact your network administrator if you're in a restricted network environment

**Note:** This is typically a network/DNS configuration issue with Home Assistant OS, not a problem with the add-on itself. The add-on needs to download the Dozzle image from Docker Hub during build, which requires proper DNS resolution.

### Agent Not Starting

**Problem:** The add-on fails to start or crashes immediately.

**Solutions:**
1. Check the **Log** tab in the add-on page for error messages
2. Verify Docker API access is enabled (should be automatic)
3. Ensure port 7007 is not already in use
4. Try restarting Home Assistant Supervisor

### Cannot Connect from Main Dozzle Instance

**Problem:** Your main Dozzle instance cannot connect to the agent.

**Solutions:**
1. **Verify the agent is running:**
   - Check the add-on status in Home Assistant
   - Review the logs for any errors

2. **Check network connectivity:**
   - Ensure your main Dozzle instance can reach your Home Assistant IP
   - Test with: `telnet [HA-IP] 7007` or `nc -zv [HA-IP] 7007`

3. **Verify firewall settings:**
   - Ensure port 7007 is not blocked by firewall rules
   - Check if Home Assistant firewall allows incoming connections on port 7007

4. **Check IP address:**
   - Verify you're using the correct IP address
   - Try using the hostname instead of IP if configured

5. **Review Dozzle logs:**
   - Check logs from your main Dozzle instance for connection errors

### No Containers Visible

**Problem:** The connection works but no containers are displayed.

**Solutions:**
1. Verify the agent has Docker socket access (should be automatic)
2. Check if containers are actually running on Home Assistant
3. Review agent logs for permission errors
4. Ensure the agent has proper privileges (configured automatically)

### Port Already in Use

**Problem:** Port 7007 is already in use.

**Solutions:**
1. Check what's using port 7007:
   ```bash
   # On Home Assistant host
   netstat -tulpn | grep 7007
   ```
2. Stop the conflicting service or change the port (requires add-on modification)

### High CPU or Memory Usage

**Problem:** The agent consumes too many resources.

**Solutions:**
1. Change `log_level` to `error` to reduce logging overhead
2. Check if there are too many containers being monitored
3. Review Home Assistant system resources

### Watchdog Restarting the Add-on

**Problem:** Supervisor logs show "Watchdog missing application response" or "Watchdog found a problem with ... dozzle-agent" and the addon restarts from time to time.

**Explanation:** The Supervisor periodically requests `http://[HOST]:7007/`. If the Dozzle agent is busy (handling many requests or streaming logs), it may not answer in time and the Supervisor restarts the addon. This is expected behavior when the agent is under load.

**Solutions:**
1. If it happens rarely, no action needed; the addon will start again.
2. If it happens often: reduce the number of containers or log streams from the main Dozzle instance, or check CPU/memory on the Home Assistant host.
3. Ensure no other service is overloading the agent (e.g. too many simultaneous connections).

### Supervisor Warnings About Config (Invalid map / Full device access)

**Problem:** Logs show "Add-on config has invalid map entry: docker_socket:rw" or "Add-on have full device access, and selective device access in the configuration".

**Explanation:** Older addon versions used `docker_socket:rw` in `map` (not a valid Home Assistant map type) and both `udev: true` and a `devices` list, which triggers a warning.

**Solution:** Update to the latest addon version. The config has been corrected: Docker access uses `docker_api: true` only, and device access uses only the selective `devices` list (no `udev: true`).

## Advanced Configuration

### Network Configuration

The add-on uses `host_network: false` with port mapping for better security (HA 2026 audit):
- Port `7007/tcp` is mapped from the container to the host
- The agent is accessible via the Home Assistant IP on port 7007 (same as before)
- The watchdog and main Dozzle instance connect to the host IP on port 7007

### Docker API Access

The add-on uses `docker_api: true` (Supervisor-provided Docker API), allowing it to:
- Access Docker API without mapping the socket
- Monitor all containers
- Read container logs

### System Permissions

The add-on requires **privileged capabilities** `SYS_ADMIN` and `DAC_READ_SEARCH` to work with the Supervisor Docker API (list containers, stream logs). Without them the agent does not function. These are configured in `config.yaml` and cause the HA security score to stay at 1; this is a known limitation for add-ons that need Docker API access.

### Security score (1–6)

Home Assistant displays a **security score from 1 to 6** for each app (6 = very secure, 1 = only run if you fully trust the source). To improve the score, this add-on follows 2026 best practices:

- **No host network:** `host_network: false`, port mapping only.
- **AppArmor profile:** `apparmor.txt` restricts container access (files, network, capabilities).
- **Read-only maps:** `config`, `ssl`, `share`, `backup`, `media` are mapped as `:ro` because the agent does not write to them.
- **Minimal permissions:** no `privileged: true`, only the strict list `[SYS_ADMIN, DAC_READ_SEARCH]` required for the Dozzle agent to list containers and stream logs via the Supervisor Docker API. Removing these breaks the add-on, so the security score remains 1.

**Codenotary signing:** for a full chain of trust, maintainers can sign images with [Codenotary CAS](https://cas.codenotary.com/) and set the `codenotary` key in `config.yaml` to the signer email. See [HA App security docs](https://developers.home-assistant.io/docs/add-ons/security) and the optional `codenotary` entry in the add-on `config.yaml`.

### Watchdog

The Supervisor pings the addon to check it is alive:
- URL: `http://[HOST]:[PORT:7007]/`
- If the agent does not respond in time, the Supervisor restarts the addon ("Watchdog missing application response" / "Watchdog found a problem with ... application")

This can happen occasionally when the agent is busy (e.g. many containers, heavy log streaming). If restarts are frequent, reduce the number of containers monitored from the main Dozzle instance or check system load. The addon does not expose a configurable watchdog timeout; that is controlled by the Supervisor.

## FAQ

### Q: Can I access the Dozzle Agent directly via web browser?

**A:** No. The Dozzle Agent is a backend service only and has no web interface. You must use a main Dozzle instance to access the logs.

### Q: Can I run multiple Dozzle Agent instances?

**A:** Yes, but each instance needs to run on a different port. The current add-on is configured for port 7007. Running multiple instances would require custom modifications.

### Q: Is this add-on secure?

**A:** The add-on uses Docker API access (via Supervisor) and minimal capabilities (SYS_ADMIN, DAC_READ_SEARCH) to list containers and stream logs. It follows HA 2026 best practices: no host network, AppArmor profile, read-only maps. Home Assistant assigns a security score (1–6); see the [Security score](#security-score-1-6) section. Ensure your Home Assistant instance is properly secured and not exposed to the internet without protection.

### Q: Can I use this with Dozzle running in Docker on the same Home Assistant instance?

**A:** Yes, but you'll need to ensure network connectivity. Since both run on the same host, you can use `localhost` or `127.0.0.1` as the IP address.

### Q: What happens if I restart Home Assistant?

**A:** The add-on is configured with `boot: auto`, so it will automatically start when Home Assistant boots.

### Q: Can I change the port from 7007 to something else?

**A:** This would require modifying the add-on configuration files. It's not recommended unless you have a specific reason and understand the implications.

### Q: Does the agent store any data?

**A:** No. The agent is a stateless service that only forwards Docker API requests. It doesn't store logs or container data.

### Q: What version of Dozzle does this use?

**A:** Check the `config.yaml` file for the `dozzle.version` field. The add-on uses a specific version of Dozzle for compatibility.
